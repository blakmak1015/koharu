# คู่มือทดสอบ koharu บน Google Colab (รุ่นฟรี, ทำมือ, รันครั้งเดียว)

เป้าหมาย: ดูว่า koharu ทั้ง pipeline (detect → OCR → แปล → inpaint → render) พร้อม LLM แปลญี่ปุ่นเป็นไทย
ทำงานบน GPU T4 ของ Colab ได้เร็วแค่ไหนและคุณภาพเท่าไร เทียบกับฟาร์มเดิม (ราว 29 วินาทีต่อหน้า, RX 6650 XT 8 GB + LM Studio gemma4 4B อีกเครื่อง)

ไฟล์ในโฟลเดอร์นี้
- `koharu_colab_benchmark.ipynb` คือโน้ตบุ๊กที่เอาไปเปิดใน Colab
- `results-form.md` คือแบบฟอร์มสรุปผล ให้กรอกหลังรันเสร็จ

## กติกา (ตามข้อตกลงของ Colab และของเรา)

1. ใช้ภาพจาก **มังงะปกติ** 5–10 หน้าเท่านั้น ห้ามใช้โดจินหรือเนื้อหา 18+ (บัญชี Google ผูกกับ GA4/GSC อยู่)
2. ห้ามต่อกับระบบจริง ไม่ใช้ manga-th.net, API, R2, ฟาร์ม หรือคิวงาน โน้ตบุ๊กนี้ไม่มีส่วนไหนต่อออกไปหาระบบเหล่านั้น
3. ห้ามเปิด server หรือ tunnel ให้คนนอกเข้า ห้ามใช้หลายบัญชีเพื่อหลบโควตา ถ้า GPU หมดโควตาให้รอวันอื่น
4. คุณเป็นคนเปิดและรันเองทั้งหมด ไม่ต้องใส่ token หรือรหัสผ่านใด ๆ

## เตรียมก่อนเริ่ม (5 นาที)

- เลือกภาพมังงะปกติ 5–10 หน้าที่ **ฟาร์มเคยแปลแล้ว** เก็บไว้ในเครื่อง (ทั้งต้นฉบับญี่ปุ่นและผลแปลของฟาร์ม เอาไว้เทียบ)
  ภาพควรมีหลายแบบ: หน้าที่มีบอลลูนเยอะ, หน้าที่มีตัวหนังสือแนวตั้งยาว, หน้าที่มีเสียงประกอบ (SFX)
- กันเวลาไว้ราว **1.5–2 ชั่วโมง** ส่วนที่นานที่สุดคือ build (30–60 นาที) และต้องเปิดแท็บค้างไว้

## ขั้นตอน

1. เปิด <https://colab.research.google.com> ด้วยบัญชี Google ของคุณ
2. เมนู **File → Upload notebook** เลือก `koharu_colab_benchmark.ipynb`
3. เมนู **Runtime → Change runtime type** เลือก **T4 GPU** แล้วกด Save
4. กดรันทีละช่องจากบนลงล่าง (คลิกในช่องแล้วกด Shift+Enter) รอให้ช่องเดิมเสร็จก่อนค่อยกดช่องถัดไป

| ขั้น | ทำอะไร | ใช้เวลาโดยประมาณ | ถ้ามีปัญหา |
|---|---|---|---|
| 1 | ตรวจ GPU และเวอร์ชันไดรเวอร์ | < 1 นาที | ถ้าบอกว่าไม่มี T4 ให้กลับไปทำข้อ 3 |
| 2 | ทำให้ไดรเวอร์รองรับ CUDA 13.3 | 1–2 นาที | ถ้าขึ้น "ทดสอบไม่ได้: ไดรเวอร์" ให้จดลงแบบฟอร์มแล้วหยุด (นี่ถือเป็นผลการทดสอบ) |
| 3 | ลง Rust, clang, Vulkan และฟอนต์ไทย Noto Sans Thai | 3–5 นาที | ถ้าภาพตัวอย่างท้ายช่องเป็นกล่อง (❌) อย่าไปต่อ ส่งข้อความในช่องมา |

| 6 | build | 30–60 นาที (รอบที่แล้ว 30.5) | ถ้ามี `error` ให้ copy 30 บรรทัดท้ายใส่แบบฟอร์มแล้วหยุด |
| 7 | อัปโหลดภาพ 5–10 หน้า | 1 นาที | — |
| 8 | ตั้งค่าแบบเดียวกับฟาร์ม | ทันที | — |
| 9 | รอบ A: Gemma 4 E4B Uncensored Q5 (ใกล้ฟาร์มที่สุด) | 5–15 นาที (รวมดาวน์โหลดโมเดล) | copy ข้อความ error ลงแบบฟอร์ม |
| 10 | รอบ B: Gemma 4 12B Uncensored (ดูว่าโมเดลใหญ่ขึ้นแปลดีขึ้นไหม) | 5–15 นาที | ถ้า out of memory ให้จดไว้แล้วข้ามไปขั้น 11 |

| 13 | ตรวจฟอนต์ไทยรอบสุดท้าย | ทันที | ถ้าขึ้น ❌ ให้ส่งข้อความในช่องมา |

5. กรอก `results-form.md` โดยดูตัวเลขจากตารางที่ขั้น 9 และ 10 แสดง กับภาพและข้อความที่ขั้น 11 แสดง
6. ปิดเครื่องด้วยเมนู **Runtime → Disconnect and delete runtime** เพื่อคืนโควตา GPU

**ถ้าเคยรันโน้ตบุ๊กรุ่นก่อนแล้วได้ภาพเป็นกล่อง:** ต้องรันใหม่ทั้งหมดตั้งแต่ขั้น 1 ด้วยโน้ตบุ๊กรุ่นนี้ เพราะ runtime เดิมปิดไปแล้ว
และรุ่นก่อนไม่ได้เก็บงานไว้ให้ render ซ้ำ หลังจากรอบนี้ ถ้ายังไม่ปิด runtime ก็ใช้ขั้น 12 render ใหม่ได้เลยโดยไม่ต้องแปลซ้ำ

- `blocks.json` ตำแหน่งคำแปลต่อบล็อก (x, y, w, h เป็นสัดส่วน 0–1 ของภาพ, ทิศตัวอักษร, ขนาดฟอนต์ที่ koharu เลือก, ข้อความไทยและญี่ปุ่น)

- `timings.tsv`, `texts.tsv`, `vram.log`, `log.txt`

## อ่านตัวเลขยังไง

- **หน้าแรก (เย็น)**: รวมเวลาดาวน์โหลดและโหลดโมเดลเข้า GPU ใช้ดูว่าเริ่มเครื่องใหม่แต่ละครั้งเสียเวลาเท่าไร
- **หน้าถัดไป (อุ่น)**: เวลาจริงต่อหน้าหลังโมเดลโหลดแล้ว ตัวเลขนี้เอาไปเทียบกับ 29 วินาทีของฟาร์ม
- **หน้า/ชม.**: คำนวณจากค่าอุ่น (3600 ÷ วินาทีต่อหน้า)
- **VRAM สูงสุด**: หน่วยความจำ GPU สูงสุดที่ใช้ระหว่างรอบนั้น (T4 มี 15 GB)
- แถว `translation` คือเวลา LLM ซึ่งเป็นคอขวดของฟาร์ม ให้ดูแถวนี้เป็นพิเศษ

## ความต่างจากฟาร์มที่ต้องรู้

- ฟาร์มส่งงานแปลไป LM Studio อีกเครื่อง ใช้ `Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q5_K_M.gguf`
  บน Colab รัน LLM ในโปรเซสเดียวกันบน T4 ด้วยรุ่น uncensored เดียวกันแต่เป็น `Q5_K_P` (ขนาดใกล้กัน koharu ไม่มีไฟล์ Q5_K_M)
  ชื่อไฟล์ GGUF ที่โหลดจริงจะพิมพ์ท้ายขั้น 9–10 และบันทึกใน `run_info.txt`
- ฟอนต์ไทย: ฟาร์มบน Windows น่าจะได้ Leelawadee UI (ฟอนต์ของ Windows) ส่วน Colab ใช้ Noto Sans Thai หน้าตาจึงต่างกันเล็กน้อย
- คำสั่งแปลคัดมาจากฟาร์ม แต่ **ไม่มี glossary เฉพาะเรื่อง** ชื่อเฉพาะจึงอาจแปลไม่ตรงกับฟาร์ม
- ไม่ได้ตั้ง `repeat_penalty = 0.05` ตามฟาร์ม เพราะบน llama.cpp ค่าต่ำกว่า 1 จะทำให้โมเดลพูดวนซ้ำ (ฝั่งฟาร์มค่านี้ไม่ได้ถูกส่งไป LM Studio อยู่แล้ว)
- ตัว render บน Colab ใช้ Vulkan แบบ CPU (lavapipe) เพราะไม่มีจอ เวลาแถว `render` จึงอาจช้ากว่าฟาร์ม
- ถ้าขั้น 2 ใช้ "ทางแก้ B" แปลว่ารันบนไดรเวอร์ CUDA ที่เก่ากว่าที่ koharu กำหนด ถ้ามีอะไรแปลก ๆ ให้จดไว้
